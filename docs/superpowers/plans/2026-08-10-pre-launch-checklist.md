# Pre-launch checklist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the thirteen open items on Ben's twenty item pre-launch checklist, so the site ships with real reviews, a privacy policy, analytics, an about page, visible breadcrumbs, a sticky mobile CTA and a response time promise.

**Architecture:** Reviews become a data file (`reviews.js`) in the same shape as `projects.js` and `pricing.js`, and the place name build check learns to strip exactly those quoted strings before scanning. New pages are added to the existing `PAGES` list in `tools/build.js`, which generates their sitemap entries automatically. Shared UI lands as partials under `tools/partials/`, following `contact-band.js`.

**Tech Stack:** Static HTML/CSS/JS generated by `node tools/build.js`. No framework. `node --test` (built into Node 20) is introduced for the build checks. `puppeteer-core`, already a devDependency, does the image conversion.

**Source spec:** `docs/superpowers/specs/2026-08-10-pre-launch-checklist-design.md`

## Global Constraints

- **No place name for Picsel, anywhere.** Not in copy, titles, meta descriptions, alt text or schema. Enforced by `findLocationClaims()` in `tools/build.js`. Client locations are facts about clients and stay allowed.
- **Review text is verbatim**, including Matthew Pinch's "unbeliveable" and his doubled full stop. The build exemption matches strings exactly, so any edit breaks it by design.
- **No `Review`, `AggregateRating` or `LocalBusiness` schema.** `Organization` with `areaServed: 'United Kingdom'` stays exactly as it is.
- **No em dashes** in any user-facing copy, page title or meta description. Neither the character nor `&mdash;`.
- **Never print a price by typing it.** Import from `pricing.js`.
- **Never state the exclusivity promise without naming Growth.**
- Titles are 60 characters or fewer. Meta descriptions are 150 to 155 characters. Both are enforced by the build.
- Every page has exactly one `<h1>`. Enforced by the build.
- **The Sitemap Law:** a new route is in `sitemap.xml` in the same commit that creates it. Adding the page to `PAGES` in `tools/build.js` does this automatically. Verify it in the build output.
- No new runtime dependencies. No framework, no CSS framework, no animation library.
- No colour, font or spacing value outside `tokens.css`.
- Content never depends on JavaScript to appear.
- Tap targets are 44x44px or larger. Test at 375, 768, 1024 and 1440px.
- Commit after every task with a real message, never `wip` or `fix`.

```js
/* ---- reviews.js — quoted Google reviews -----------------------------------
   Four real reviews, rendered from reviews.js and never retyped. See that

   The link to the Google profile is the point of the section rather than a

   web person, and a quote on a website proves nothing on its own. A quote that
   can be checked in one click proves something. */

import { SITE } from '../../site.config.js';
import { escapeHtml } from '../templates/page.js';

/**
 * @param {object}   options
 * @param {object[]} options.reviews    Records from reviews.js.
 * @param {string}   options.heading
 * @param {string}   options.headingId  Unique per page, for aria-labelledby.
 */
export function renderReviews({ reviews, heading, headingId }) {
  if (!reviews.length) return '';

  const items = reviews
    .map(
      (review) => `          <figure class="review">
            <blockquote class="review__quote">
              <p>${escapeHtml(review.text)}</p>
            </blockquote>
            <figcaption class="review__who">
              ${escapeHtml(review.author)}
              <time class="review__date" datetime="${escapeHtml(review.date)}">${formatDate(review.date)}</time>
            </figcaption>
          </figure>`,
    )
    .join('\n');

  return `    <section class="reviews" aria-labelledby="${escapeHtml(headingId)}">
      <div class="wrap">
        <h2 class="reviews__heading" id="${escapeHtml(headingId)}">${escapeHtml(heading)}</h2>
        <div class="reviews__list">
${items}
        </div>
        <p class="reviews__source">
          Every one of these is on
          <a href="${escapeHtml(SITE.reviewsUrl)}">Picsel's Google profile</a>, word for word.
        </p>
      </div>
    </section>`;
}

    day: 'numeric',
    month: 'long',
    year: 'numeric',
    timeZone: 'UTC',
```

- [ ] **Step 1: Write the partial**

```js
/* ---- breadcrumbs.js — the visible trail -----------------------------------
   Fed the SAME array that schema.js's breadcrumbs() turns into JSON-LD. That
   is the whole design: a trail a reader sees and a trail Google reads that are
   generated from one argument cannot drift apart, and drift is the normal
   failure here. The schema said /work/ and the page said Home for months on
   plenty of sites.

   The last crumb is the current page and is not a link. Linking a page to
   itself gives a reader a control that does nothing. */

import { escapeHtml } from '../templates/page.js';

export function renderBreadcrumbs(trail) {
  const items = trail
    .map((crumb, index) => {
      const isLast = index === trail.length - 1;
      const inner = isLast
        ? `<span aria-current="page">${escapeHtml(crumb.name)}</span>`
        : `<a href="${escapeHtml(crumb.path)}">${escapeHtml(crumb.name)}</a>`;
      return `          <li class="breadcrumbs__item">${inner}</li>`;
    })
    .join('\n');

  return `    <nav class="breadcrumbs" aria-label="Breadcrumb">
      <div class="wrap">
        <ol class="breadcrumbs__list">
${items}
        </ol>
      </div>
    </nav>`;
}
```

```js
    <a class="sticky-cta__call" href="${escapeHtml(SITE.contact.phoneHref)}">Call ${escapeHtml(SITE.contact.phoneDisplay)}</a>
```
